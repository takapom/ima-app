# 製品仕様

## 目的と対象

大切にしたい人と外出中に「次どこへ行くか」を探す役の負荷を減らす。対象をカップルだけに限定せず、その場の気分・体力・予算に合う次の行き先を決める。
事前の旅行計画、予約代行、網羅的な店舗検索は対象に含めない。

## 基本の体験

1. 自由記述、入力候補、現在地、今夜の条件から探索を始める。
2. LLMが探索・詳細取得・提示を選ぶ。意図の理解、追加質問、店舗カードと選定理由の提示は[AIの振る舞い](philosophy/ai-behavior.md)に従う。
3. 新しい候補は最大3件を同じ大きさ・同じ操作のコンパクトなカードで並べる。提案順は維持し、1件目だけを大きく強調しない。説明・比較・確認はメッセージだけでもよい。
4. 提案後の追記、条件変更、比較、却下を同じ対話で受け付ける。変更されていない要望を引き継ぎ、変更点が分かれば再提案し、不明なら追加質問を返す。
5. どの候補カードからも直接「店舗詳細を見る」で店舗情報を確認し、詳細内の「ここにする」で決定して地図や共有へ進む。決定前でもカードの地図ボタンでGoogle Mapsを開ける。「残す」で保存した候補は保存一覧から参照する。

候補数を満たすために不適合な候補を追加しない。候補0件を成功したカード集合にせず、不足・失敗・再試行を区別する。モデルの応答確定とユーザーの決定・保存は別の操作である。

## 画面と操作

- iPhone向けの日本語・ダークUI。単一キャンバスで`Empty → Working → Results → Decided`を表し、通信失敗や未設定も表示する。
- 起動のたびにスプラッシュを表示し、犬が「チャットで話す」「質問に答える」を尋ねる。選んだ入口は記憶しない。チャットは上記の会話へ入る。質問は誰と・ジャンル・ジャンルごとの系統・予算・雰囲気の5問で、答え終えると完了の印と回答を見せ、回答を1文にまとめて会話の最初の発言として送る。雰囲気は好みとして伝えるだけで、静かさなどを保証しない。会話の準備中はスプラッシュのまま待ち、未設定・接続失敗で会話を使えないときは入口を出さずにその表示を出す。
- 会話画面の右下には犬が常にいて、検索中は走り、決定後は喜ぶ。送信失敗・取り消しでは困った姿にする。Workerが「検索したが候補0件」と示した最新の応答でだけ「見つからなかったわん」と言い、失敗や推測では言わない。
- 自由入力、ユーザーバブル、条件編集、候補カード、説明・比較メッセージを扱う。会話は発言順に表示し、古い発言は追加で読み込める。写真領域だけを横スクロールする。
- 写真が提供されていない候補は写真欄とその余白を設けず、店舗名・説明を表示する。主提案・別候補の両方に適用し、写真の読み込み中・取得失敗とは区別する。
- Drawerは会話履歴、条件、保存一覧、設定への入口。会話タイトルを選ぶと保存済み発言から続行でき、新しい会話・削除もここから行う。古い応答や期限切れ内容を新しい結果に見せない。
- 設定はDrawerから全画面で開き、閉じると会話へ戻る。現在地・探し方・データ・このアプリについての項目を並べるだけで、どの行も操作を受け付けず準備中と示す。実装前の値や状態を表示せず、アカウント連携・端末間同期・テーマ・言語の切り替えは項目に持たない。今夜だけの条件と保存済み条件は条件編集が持ち、設定へ二重に置かない。
- 候補の詳細シートは端末内の表示可能な店舗情報と取得済み写真だけを使い、営業時間・定休日・アクセス・住所・予算の全文、設備の有無・一部対応と補足、出典を表示する。閲覧による追加通信・永続化は行わず、「ここにする」「残す」と出典リンクは既存の処理につなぐ。
- 出典のない詳細は開かず、候補の除外・カード集合の差し替え・出典の表示期限切れで閉じる。一部情報の期限切れ時は該当項目を除去し、未取得・期限切れの写真枠は設けない。
- 候補カードは写真・ジャンル・店名と、アクセス・掲載営業時間・予算をアイコン付きで並べる。操作は右端に縦に並べた保存と地図（ピンのアイコンのみ）の丸ボタン、下段の主ボタン「店舗詳細を見る」の3つに絞り、店舗ページURLは表示しない。
- 地図ボタンは、表示可能な店名と住所（なければエリア）を検索語にしたGoogle Maps検索URLを外部で開く。Google APIの呼び出し・APIキー・座標の推定は行わず、店名等が表示不可・期限切れならボタンを出さない。
- 詳細シートには、表示可能な店舗情報に含まれる店舗ページURLを全文で折り返して表示し、未提供・表示不可なら行ごと省く。タップ時は取得したURLをクエリも含めて既存の外部リンク処理で開き、詳細シートは先に閉じる。
- 位置情報は明示操作で取得する。拒否・低精度・タイムアウトを区別し、IPなどから補わない。
- 発話や履歴に地名がなければ、場所を聞き返さず、取得できた現在地の周辺をまず1km圏で探し、少なければ3km圏まで広げる。地名があれば地名で探す。現在地が使えない（拒否・低精度・タイムアウト・取得不可）ときは現在地で探さず、理由を伝えて駅名や地名を尋ねる。

具体的な描画とトークンは[mobile実装](../apps/mobile/src)を参照する。

## 根拠と条件

営業時間・価格・設備などの事実は取得した根拠に結び付ける。掲載情報を現在の空席・入店・静かさの保証へ変換しない。不明、未対応、取得失敗、方針による非公開を区別する。

必須条件は、根拠が不足しても黙って解除しない。変更はユーザーの発話に基づく。
徒歩時間・終電・最低滞在・帰宅駅は扱わない（[#55](https://github.com/takapom/ima-app/issues/55)で撤去）。条件編集・候補チップ・保存済み条件・モデルへの提示のいずれにも出さない。ユーザーが発話で述べた場合は確認できないことを伝え、取得できる情報だけで提案する。

## 会話履歴

- 会話一覧は更新順。タイトルは最初のユーザー発言から作る。アプリを開き直しても、同じowner credentialで過去の会話を選択できる。
- ユーザー原文は会話削除まで保持する。回答・店舗情報は保持条件に従い、保存不可や期限切れの本文はその状態を表示する。その場で表示可能な回答と、後から復元可能な本文は区別する。
- 日をまたいだ続行でも会話IDは維持する。以前の店舗情報を現在の情報として使わず、必要な情報を再取得する。
- 通信が切れても受理済み発言は残り、履歴の再取得で処理状態を確認できる。会話の切り替え後に、前の会話の回答を混ぜない。
- 同じcredentialを持つ利用が対象。アカウント連携や端末間のcredential移行は提供しない。

## 保存と今夜の範囲

- 保存済み条件・店舗参照・決定時刻はowner単位で残す。端末はサーバー値を投影し、更新・再取得の失敗や古さを隠さない。
- 今夜だけの条件編集は保存済み条件を変更しない。
- 現行の「ここにする」は未保存の候補も参照として登録するため、保存一覧にも現れる。お気に入り専用フラグの分離や訪問済み管理は行わない。
- 今夜の表示期限はJST 05:00。05:00より前の作成は当日、05:00以後は翌日を期限とし、再起動で延長しない。
- 店舗参照と、名称・写真・住所などのProvider内容を分ける。保存一覧から再取得できなければ参照のみの状態を示す。

用途別の許可・保持期限は[Providerポリシー](provider-policy.md)に従う。地図・共有でも帰属や出典を維持し、Provider内容の地図転用許可を推測しない。

## 提供範囲

店舗検索・詳細はホットペッパー グルメサーチAPIを使う。掲載営業時間・定休日・予算目安・設備を根拠にし、営業状況が未確認でもその旨を表示して候補を提示する。取得できた店舗トップ写真1枚を出典付きで候補カードへ表示する。営業終了が明示された候補や必須条件を検証できない候補は確定しない。徒歩経路・終電は提供しない。保存一覧からの店舗再取得は現在の接続では提供しない。
開発用fixtureは同じAdapterへ合成店舗を渡し、実店舗の営業状況を測定した結果ではない。
実API、実モデルの品質、実機、署名、App Attest、利用条件はそれぞれ検収する。内部動作確認を外部TestFlightの配布完了に読み替えない。
未実装・未決事項と完了判定は[GitHub Issues](https://github.com/takapom/ima-app/issues)で管理する。
