# 製品仕様

## 目的と対象

大切にしたい人と外出中に「次どこへ行くか」を探す役の負荷を減らす。対象をカップルだけに限定せず、その場の時間・体力・予算・帰宅条件に合う次の行き先を決める。
事前の旅行計画、予約代行、網羅的な店舗検索は対象に含めない。

## 基本の体験

1. 自由記述、入力候補、現在地、今夜の条件から探索を始める。
2. LLMが探索・詳細取得・提示を選ぶ。意図の理解、追加質問、店舗カードと選定理由の提示は[AIの振る舞い](ai-behavior.md)に従う。
3. 新しい候補は主提案1件＋別案0〜2件。説明・比較・確認はメッセージだけでもよい。
4. 提案後の追記、条件変更、比較、却下を同じ対話で受け付ける。変更されていない要望を引き継ぎ、変更点が分かれば再提案し、不明なら追加質問を返す。
5. 「ここにする」で決定し、地図や共有へ進む。残したい候補は保存一覧から参照する。

候補数を満たすために不適合な候補を追加しない。候補0件を成功したカード集合にせず、不足・失敗・再試行を区別する。モデルの応答確定とユーザーの決定・保存は別の操作である。

## 画面と操作

- iPhone向けの日本語・ダークUI。単一キャンバスで`Empty → Working → Results → Decided`を表し、通信失敗や未設定も表示する。
- 自由入力、ユーザーバブル、条件編集、候補カード、説明・比較メッセージを扱う。写真領域だけを横スクロールする。
- 写真が提供されていない候補は写真欄とその余白を設けず、店舗名・説明を表示する。主提案・別候補の両方に適用し、写真の読み込み中・取得失敗とは区別する。
- Drawerは今夜の履歴、条件、保存一覧への入口。古い応答や期限切れ内容を新しい結果に見せない。
- 「ちがう」は今夜の却下として同じ対話へ送信し、LLMの再提案または追加質問につなぐ。却下理由を補わず、永久的な嗜好の拒否や訪問状態へ変換しない。
- 位置情報は明示操作で取得する。拒否・低精度・タイムアウトを区別し、IPなどから補わない。

具体的な描画とトークンは[mobile実装](../apps/mobile/src)を参照する。

## 根拠と条件

営業時間・価格・徒歩・終電などの事実は取得した根拠に結び付ける。掲載情報を現在の空席・入店・静かさの保証へ変換しない。不明、未対応、取得失敗、方針による非公開を区別する。

必須条件は、根拠が不足しても黙って解除しない。変更はユーザーの発話に基づく。GPSが不十分な場合は地域名で検索できても、徒歩条件を満たすと確定できない。終電は検証済みの運行日・経路データを必要とし、架空の時刻を補わない。
根拠を取得できるProviderがない条件は、そもそも指定経路を提供しない。現在の接続では徒歩上限と帰宅駅がこれにあたり、条件編集・候補チップ・モデルへの提示のいずれにも出さない。ユーザーが発話で述べた場合は未対応として明示し、条件として採用しない。これは設定済みの必須条件を解除することとは別である。

## 保存と今夜の範囲

- 保存済み条件・店舗参照・決定時刻はowner単位で残す。端末はサーバー値を投影し、更新・再取得の失敗や古さを隠さない。
- 今夜だけの条件編集は保存済み条件を変更しない。`station_label`は端末内の表示情報である。
- 現行の「ここにする」は未保存の候補も参照として登録するため、保存一覧にも現れる。お気に入り専用フラグの分離や訪問済み管理は行わない。
- 今夜の表示期限はJST 05:00。05:00より前の作成は当日、05:00以後は翌日を期限とし、再起動で延長しない。
- 店舗参照と、名称・写真・住所などのProvider内容を分ける。保存一覧から再取得できなければ参照のみの状態を示す。

用途別の許可・保持期限は[Providerポリシー](provider-policy.md)に従う。地図・共有でも帰属や出典を維持し、Provider内容の地図転用許可を推測しない。

## 提供範囲

店舗検索・詳細はホットペッパー グルメサーチAPIを使う。掲載営業時間・定休日・予算目安・設備を根拠にし、営業状況が未確認でもその旨を表示して候補を提示する。取得できた店舗トップ写真1枚を出典付きで候補カードへ表示する。営業終了が明示された候補や必須条件を検証できない候補は確定しない。徒歩経路・終電・保存一覧からの店舗再取得は現在の接続では提供しない。
開発用fixtureは同じAdapterへ合成店舗を渡し、実店舗の営業状況を測定した結果ではない。
実API、実モデルの品質、実機、署名、App Attest、時刻表、利用条件はそれぞれ検収する。内部動作確認を外部TestFlightの配布完了に読み替えない。
未実装・未決事項と完了判定は[GitHub Issues](https://github.com/takapom/ima-app/issues)で管理する。
