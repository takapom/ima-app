# ADR 0009: 質問に応じて候補UIとメッセージを組み合わせる

- **Status:** Accepted（方向性。パターン・スキーマは未決）
- **Date:** 2026-09-08
- **Supersedes (in part):** 0001・0003のアシスタント本文を出さず毎回候補UIで返す制約、0008のsubmit_cardsを全応答の終端と解釈する前提

## Decision

LLMはHTMLモックの主提案1 + 別案最大2の候補UIに加え、メッセージも返せる。毎回候補UIを返す必要はなく、ユーザーの質問と会話文脈に応じてLLMが適切な提示を選ぶ。他の提示形式の具体的な種類は未決。

Applicationが質問を分類して固定の出力へ振り分ける方針にはしない。応答パターンはLLMへの指針と評価ケースとして整理する。

初期のモデル向け操作3つ（search_places / get_place_details / submit_cards）とヘキサゴナル構成は維持する。メッセージのみで完了する応答も必要となるため、全ターンでsubmit_cardsを必須とする前提は見直す。具体的な最終応答プロトコルは次の設計で決める。

HTMLモックは候補UIの見た目・操作の参照であり、LLMが生HTMLを生成する決定ではない。

## 次の設計

[自律応答ループの実装設計案](../design/0004-autonomous-response-loop.md)に、ユーザーの要求充足を最優先とする具体構造・最終応答契約・評価を記載。詳細は設計案として区別する。

[応答パターン案](../design/0003-response-patterns.md)で、質問の目的、提示形式、調査の要否、既存候補の扱いを検討する。メッセージ・UIの構造化形式、表示更新と履歴、submit_cardsとの接続は未決。
