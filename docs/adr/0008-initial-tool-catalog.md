# ADR 0008: 初期のモデル向け操作を3つに限定する

> 実装に向けた詳細案: [初期3操作の詳細設計 v1](../design/0005-tool-contracts-v1.md)。3操作の採択は維持し、新しい型・数値・検証条件はReview-readyの提案として区別する。

- **Status:** Accepted
- **Clarified by:** [0009](./0009-contextual-response-presentation.md)（3操作は維持。全応答でsubmit_cardsを必須としない提示方針）
- **Date:** 2026-09-08
- **Deciders:** プロダクトオーナー（本議論）
- **Supersedes (in part):** [0007](./0007-llm-led-tool-orchestration.md) のTool数を最小化しない選定方針・3操作への限定を採用しない記述

## Decision

初期のモデル向け操作は次の3つに限定する。

| 操作 | 用途 | 位置づけ |
|---|---|---|
| `search_places` | 気分・目的に合う候補を探す | 探索能力 |
| `get_place_details` | 特定候補の不足情報を調べる | 追加調査。供給可能な項目だけ |
| `submit_cards` | 主提案と別案を選んで確定要求する | Applicationの終端操作 |

0007のLLM主導の探索は維持する。LLMが必要な操作・引数・追加調査・比較を選び、Applicationは実行基盤・状態管理・出力契約の検証を補う。3操作を必ず順番に実行する固定パイプラインにはしない。

`submit_cards`は外部情報を取得するAdapterではない。モデル向けの呼び出し面を持つApplicationの確定操作であり、契約違反はLLMへ返す。

Toolはアプリの状態や提案方針を所有しない。モデル向けの公開面と、内部のPort・Adapterの数は一致させる必要がない。

この決定は初期スコープであり、将来の能力追加を禁止しない。供給できない情報を推測で埋めたり、3操作に限定するために未実装の能力を実装済みとして扱ったりしない。

## 未決・次の作業

次は3操作の入力・出力契約を定義する。

1. `search_places`: 検索条件、モデル指定値とHarness注入値、候補のIDと返す事実。
2. `get_place_details`: 要求可能な情報項目、供給元、未対応・不明の表現、出典・取得時刻。
3. `submit_cards`: 候補ID、理由・比較文、必須根拠、検証エラー、部分結果の扱い。

特に営業・徒歩・終電の情報をどの操作で取得できるかは未確定。既存の出力検証要件と矛盾しないように能力範囲を具体化する。これらをApplicationが自動で調べる方針は採択しない。
