# ADR 0002: 大切にしたい人、探す役の負荷、リスト

- **Status:** Accepted
- **Date:** 2026-09-06
- **Deciders:** プロダクトオーナー（本議論）
- **Tags:** product, job, target, save
- **Supersedes (in part):** [0001](./0001-in-the-moment-next-spot.md) の対象（カップル先行）、責任の置き方（二人とも背負わない）、結果ラベル（行った / 入れた / 合った）

0001 の骨格は維持する。覆すのは「誰の、どの重荷を、何として残すか」だけである。

維持するもの:

```
自由記述 → エージェント探索 → 主提案1 + 別案2 → ここにする → 地図 / LINE
```

歩道の90秒、今行ける3件、終電のある都市の夜、LINEは決定後、機能は条件と保存の2つ。

---

## 1. Context

0001 は物語をカップルに置き、ジョブを「どちらも決断の責任を全部背負わない」とした。複利は「行った / 入れた / 合った」が残ることだとした。

その後の修正:

- 相手はカップルに限らない。友達でも、初めましてでもよい。共通点は **大切にしたい人と過ごしている時間** である
- 二人の責任を消すのではない。実際にスマホを出して探す側の負荷を軽くする
- その店に行ったかどうかは、今は重要ではない。残したいのはリストである

0001 の Couples 先行、相互免責、訪問検証は、この3点と衝突する。

---

## 2. Decision

### 2.1 対象は関係の種類ではなく、大切にしたい人との時間

**Decision:** セグメントをカップルに固定しない。雇われる場面は、今いっしょにいる相手を大切にしたいときである。

入る:

- 付き合っている二人
- 友達
- 初めまして（初対面の食事のあと、を含む）

まだ入らない（0001 と同じ）:

- 人数の多い二次会の幹事（3人以上、席、合流）
- 明日のデートプラン
- 関係の記録（記念日、アルバム、相手ごとのプロフィール）

関係種別を選ばせる UI は作らない。コピーも「デート」「カップル」を主語にしない。状況は「ご飯終わり」「まだ話していたい」「終電まで」で足りる。

最初の楔は 0001 のまま、**終電がある都市の夜・少人数（まず2人）**。友達だから昼のカフェ、初めましてだからマッチング導線、にはしない。

### 2.2 雇う人は、探す役になる側である

**Decision:** ジョブは「二人とも責任を負わない」ではない。**片方（探す役）の責任を軽くする。**

現実は一台である。書く人、送る人、`ここにする` を押す人がいる。その人はいつも決める人か、沈黙に耐えられない人か、今夜のホストである。相手は受益者であって、最初のユーザーではない。

軽くするもの:

- マップを開いてピンを比較する時間
- 「俺が決めた店がハズレだった」の重荷
- 相手に「どこがいい？」と返し続けること

残してよいもの:

- 最終的に片方の指で決まること
- 相手が「それはちょっと」と言うこと（別案2がそれを受ける）
- 決めた店を LINE で渡すこと（相手はアプリ不要）

状況つきジョブ文（0001 の 3.1 を置き換え）:

> When 大切にしたい人と外出していて、今の予定が終わり、「次どこ行く？」が出て、残り時間はあるが候補が頭にない  
> I want to 探す役のまま、今行ける場所をすぐ出せる  
> so I can 相手に選ばせ続けず、自分も長時間の探索とハズレの全責任を負わずに、今夜を先に進める

成功指標（0001 の歩行・90秒は維持。相互の我慢と訪問検証は外す）:

- 探す役が候補を出すまでの時間（目標: 90秒以内）
- 相手に画面または LINE で渡せたか
- 今夜が次の場所へ動いたか（歩いたかは任意。帰宅とマップ逃げを減らせたか）
- 探す役が「全部自分が決めた」感をどれだけ下げられたか
- スマホを見ていた時間が、その場の空気を殺さなかったか

やらない解釈:

- エージェントが決めたことにして、人間の選択を消す
- 二人同時ログインや共有セッションを必須にする
- 「どちらが悪くないか」をプロダクトの売りにする

主提案1件は、探す役が「これがある」と出せるためのものである。免責装置ではない。

### 2.3 訪問結果は追わない。保存はリストである

**Decision:** 「行った / 行ってない / 入れた」は NVP の指標にも、保存の主構造にもしない。`保存` はリストである。

0001 の複利仮説:

```
その場で決めて行った → 状況×結果のラベルが残る → 同じエリア・時間帯の次回が速くなる
```

これは採択しない。訪問の真偽を取るコストに対して、今ほしい残渣は **また出せる店の一覧** である。

リストに入るもの:

- `残す` した店（また行きたい）
- 今夜 `ここにする` した店（決めた、として残る。歩いた証明ではない）
- 将来、手動で足した店

リストにしないもの:

- 着いたかのプッシュ
- 入れたかの確認
- 「ちがう」を永久の行かないへ自動で積むこと（今夜の却下と、二度と出さない、は別）

`保存` の中身（0001 の3状態を置き換え）:

```
保存
────────────────
残した店     ← また出したい
今夜決めた   ← ここにするした店。訪問の真偽は持たない
```

「行かない」は緊急の `ちがう` から自動で作らない。出さない設定が必要になったら、その時に明示する。

`残す` は緊急操作の主ボタンにしない（0001 4.3 は維持）。リストは今夜の決定のあと、またはカード上の小さい操作で足りる。リスト化が先のジョブになると、ソファで貯めるプランナーになり、0001 が却下した道に戻る。

相手ごとのリスト、共同リスト、関係グラフは、相手プロフィールと同じ棚なので今はやらない。リストはまず **この端末の店リスト** である。

## 3. 0001 から読み替えるもの

| 0001 | 0002 |
|---|---|
| ターゲットはまずカップル | 大切にしたい人（カップル / 友達 / 初めまして） |
| どちらも責任を全部背負わない | 探す役の負荷を軽くする |
| 成功: 歩いた / 入れた / 我慢しなかった | 成功: 探す役が90秒で出せた / 相手に渡せた / 今夜が動いた |
| 保存 = 行った / また行きたい / 行かない | 保存 = 残した店 / 今夜決めた |
| 複利 = 状況×結果ラベル | 複利は主張しない。残渣はリスト |
| 最初から友達向けは却下 | 友達・初めましては対象に含む。二次会（3+）はまだ外 |

NVP の核は残す:

> 都心の夜、食事の直後、終電制約がある状態で、大切にしたい人と二人いる探す役が、自由記述1回から「今行ける」最大3件を出し、90秒以内に次へ進める。

「歩ける」は望ましいが、検証の必須条件ではない。必須は **探す役が候補を出し、今夜が止まらないこと**。

## 4. Consequences

良い結果:

- コピーと導線が「デートアプリ」に見えない
- ユーザーが一人でよい（相手は LINE で足りる）ことが、ジョブと一致する
- 訪問トラッキングを捨てるので、プレリリースの計測が軽くなる
- 保存の意味が、ブックマークとして説明できる

悪い結果・負債:

- 「大切にしたい人」は動機であり、配布セグメントではない。最初の10夜はまだエリアと時間帯で切る必要がある
- 訪問ラベルを捨てると、提案が利用ごとに良くなる、とは言えなくなる。それは今は主張しない
- リストは Maps の保存・Instagram の保存と衝突する。差は、リストが **今夜その場で出た店** から積まれること。ソファで店を集める機能にすると差が消える
- 初めましては頻度が低く、友達・カップルは繰り返す。リストの価値は後者に寄る。それでも対象から初めましてを外さない
- `ここにする` した店をリストに残すと、行かなかった店も混ざる。今はそれでよい。行ってないを掃除しない

リリース後に失敗しやすい形（追加）:

- 関係種別の選択や「相手を登録」を足して、歩道で開かれなくなる
- リストをメイン画面にして、今行く道具でなくなる
- 探す役を消そうとして、二人合意フローを足す

---

## 5. 未決（この決定でも開けておく）

- リストの名前（残した / 今夜、以外の呼び方）
- 今夜決めた店と、残した店を、一つの一覧にするか分けるか
- 相手にリストを見せるか（当面は LINE で店を1件送る）
- 提案精度のためのログを内部で取るか（ユーザーには見せない。訪問確認はしない）
