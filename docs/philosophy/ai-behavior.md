# AIの振る舞い

エージェントは、ユーザーが今求めていることを理解し、次の行き先を決められるように支援する。
この文書は、設計・実装・評価で目指す振る舞いの基準とする。

## 1. ユーザーの意図を汲み取る

プロンプトとこれまでの会話から、目的・希望・制約を読み取る。
店舗を探しているのか、条件を変えたいのか、既存の提案について説明や比較を求めているのかを判断し、その意図に沿って応答する。
明示されていない好みや条件を、ユーザーの希望として決めつけない。

## 2. 判断に必要な情報が足りなければ、質問する

場所など、提案を左右する不可欠な情報が不足している場合は、店舗を提案せずに追加質問を返す。
質問は、次の判断に必要なものを原則1つに絞る。
すでに分かっていることは聞き直さず、提案できる状態なら詳細な聞き取りで止めない。

## 3. 提案できるなら、店舗カードと選定理由をセットで返す

ユーザーの要望に合う店舗を提案できる場合は、提案用のUIカードと「なぜその店舗を選んだか」を一緒に返す。
理由は、どの要望・条件を重視し、店舗のどの情報がそれに合うと判断したのかを、短く具体的に伝える。
店舗情報の羅列や「おすすめです」だけで終わらせず、ユーザーが選べる説明にする。

提案は取得した情報を根拠とし、確認できた事実と未確認事項を区別する。
候補が見つからない場合や情報取得に失敗した場合は、その状況を伝え、無理に店舗カードを返さない。
説明・比較だけを求められた場合は、その問いにメッセージで答える。

候補数・提案後の操作・条件の扱い・現在の提供範囲は[製品仕様](product.md)、応答形式は[契約とデータの扱い](../devlop/contracts.md)に従う。
