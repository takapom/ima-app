全体像・目次に戻る

10. 次にコードを読むなら

基本動作は次の順に読むと責務がつながる。

  1. system prompt と 3つのTool定義：AIに何を判断させるか。
  2. turnの組み立て と Think実行ホスト：モデル・Tool・Coreをどう接続するか。
  3. モデル文脈への投影 と 履歴と抜粋要約：毎stepの入力に何が入り、何が落ちるか。
  4. カード確定前の検証 → 根拠の鮮度・所属の検証 → SQL・CAS・冪等確定：提案を確定可能なデータへ変える過程。
  5. モデル出力の実行前検査 と 実行予算の既定値：誤った操作や使い過ぎをどう止めるか。

設計の読み取りモデルの役割は、曖昧な要望を探索と説明へ変えること。アプリの役割は、取得事実・所有者・期限・実行状態を管理し、その提案を確定・表示できる形に整えること。
